# Engineering methods in Pi

Load the complete engineering Pi package. Its task-specific skills and bundled agreement own
engineering methods; project guidance owns product contracts. Use the actual skill inventory
and commands such as `/skill:implement-task` or `/skill:code-review` when explicit invocation helps.
Check each command's actual source path: Pi can discover user `.agents/skills` even with a separate
agent directory, and duplicate names can shadow this package. For an isolated invocation, use
`--no-skills --skill` with the complete installed package's `skills` directory. Preserve its sibling
references. Do not remove or overwrite other packages to resolve a collision without permission.

Use Pi's native session, print/JSON, RPC or SDK interface as appropriate. A method that benefits
from independent work does not imply that a delegation extension exists. Inspect available tools
and packages and report any unmet independence or tool requirement without fabricating it.

Pi's default process permissions are not an application sandbox. Run under the approved host or
container policy, keep credentials scoped, and preserve the user's authority for external actions.
Project trust for loading resources is distinct from filesystem, network and process isolation.

On continuation, validate actual workspace and operation state before acting on a saved summary.
Retain objective, constraints, evidence, failed hypotheses and the next authorized action.
