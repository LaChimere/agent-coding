# Reframe

Work from the user's actual files, code and wording, not from a summary of them. This skill reads
and looks things up; it changes nothing. Search with general terms, and keep private names and code
out of web queries.

When the description could point at several problems, start by listing the two or three likeliest,
each with the term that names it and the sign that separates it from the others. Then continue with
the most probable one and give your reason.

1. **Vocabulary.** List the terms that would most change what gets built, up to about a dozen, the
   most consequential first. For each one, give the term and its plain meaning in one sentence, the
   part of the user's description it names, a link to a real project, paper or system using it in
   this sense, and what the term lets the user ask an agent for.
2. **Nearby fields.** Choose two or three fields that solved a problem of the same shape under other
   names. For each one, say what transfers, where the comparison fails and which terms it adds.
3. **Gaps.** Name what the user left out but should care about.
4. **Rewrite.** Rewrite the user's description with the new terms.

Open every link and check that it uses the term in the meaning you gave. Drop any citation you
cannot check, and mark each term left without a checked source. Explain in the user's language,
but give each term in the form practitioners search for. Include only items that tell the user
something new.
