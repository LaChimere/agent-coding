# Reframe

Work from the user's own files, code and wording rather than a summary of them. This skill reads
and looks up sources; it changes nothing.

When the description could name more than one problem, first list the two or three candidate
problems. Give each the term that names it and the sign that tells it apart from the others, then
continue with the most likely one and say why you chose it.

1. **Terms.** Give eight to twelve terms, ordered by how much each would change what gets built.
   For each, give the term and its meaning in one plain sentence, the part of the user's
   description it names, one real project, paper or system that uses it in that sense with a
   link, and what the term lets the user ask an agent for.
2. **Neighboring fields.** Pick two or three fields that solved the same shape of problem under
   other names. For each, say what carries over, where the analogy breaks and which terms come
   back from it.
3. **Blind spots.** Name what the user did not mention but should care about.
4. **Rewrite.** Rewrite the user's description with the new terms.

Open every link and confirm it uses the term in the stated sense; remove any citation you cannot
confirm. Explain in the user's language and keep each term in the form practitioners search for.
Every item should carry information the user lacked.
